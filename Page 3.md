# Research Strategy / Technical Approach

## 3. Training, Integration, and Evaluation Plan

The Phase I effort is designed as a **bounded proof of concept** that establishes a clear, end-to-end scientific reasoning workflow and quantitatively evaluates whether the proposed architecture is on a credible trajectory toward transformative capability. This scope is directly aligned with the Genesis Mission phased-program structure, which states that Phase I should demonstrate a tangible research workflow, evaluate potential AI advantage, and provide evidence that the proposed approach can scale in impact with additional data, compute, or model development. Accordingly, our goal in the initial nine-month effort is not to build a maximally scaled universal scientific AI platform, but to construct and test a prototype system that captures the essential architectural properties of **19C-style composable and modular foundation models** in a demanding biological domain.

### 3.1 Phase I Training Strategy

Training in Phase I will proceed along two distinct but coordinated tracks: **(1) adaptation of the base scientific LLM orchestration layer**, and **(2) pretraining of the prototype viral protein foundation model**. These tracks are intentionally separated because they serve different scientific purposes. The base LLM is responsible for reasoning control, task decomposition, tool selection, and evidence synthesis; its value depends on reliable orchestration behavior rather than biological representation learning alone. By contrast, the viral protein foundation model is responsible for learning domain-specific sequence representations and mutation-context priors that reflect the biological regularities of viral proteins.

For the **base scientific LLM**, we will use a governed adaptation strategy rather than attempting frontier-scale pretraining during Phase I. Adaptation data will include curated examples of scientific task decomposition, tool-routing demonstrations, multi-step reasoning over heterogeneous evidence, and structured workflow exemplars relevant to viral biology. We will emphasize supervised and synthetic task traces that teach the model when to invoke specialized agents, how to interpret returned outputs, how to maintain provenance records, and how to synthesize evidence into testable scientific statements. The objective is to produce a dependable orchestration model capable of **agentic scientific planning** and **audit-friendly evidence integration**, which is directly responsive to Topic 19’s emphasis on AI systems that use tools and function in iterative scientific workflows. 

For the **viral protein foundation model**, we will assemble a curated training corpus of viral protein sequences with supporting metadata where available, including subtype, clade, protein identity, region annotations, and mutation context. In Phase I, we will deliberately constrain model scale and corpus complexity so that the effort remains focused on demonstrating representation value rather than chasing scale for its own sake. Pretraining objectives will include masked residue modeling and other sequence-context tasks designed to capture viral sequence regularities, functional constraints, and mutation-dependent context. We will also explore limited auxiliary objectives that encourage the model to preserve biologically meaningful neighborhood structure in embedding space, especially for related variants and mutation clusters. The key technical deliverable is a **specialized prototype module** whose learned representations can be consumed by the larger multi-agent reasoning system. This approach is consistent with Focus Area 19C because the viral model is developed as a reusable, integrable specialized foundation model rather than as a stand-alone endpoint.

For the remaining agents—Structure Reasoning, Evolutionary Dynamics, Quantitative Inference, and Evidence—we will prioritize **adapter-based integration and task-specific wrapping** over full model pretraining. In Phase I, the scientific value of these agents comes primarily from their integration into the system and their ability to produce structured, provenance-aware outputs. Accordingly, we will build wrappers around selected structure-analysis, phylogenetic, statistical, and retrieval tools, and we will add lightweight reasoning or translation layers that convert raw outputs into machine-readable evidence objects. This is both scientifically and programmatically appropriate: the FOA emphasizes flexible integration and workflow performance, not the invention of entirely new tools in every component.

### 3.2 Integration Strategy and System Assembly

System integration will proceed in staged form to reduce technical risk and preserve traceability. In the first stage, each agent will be developed and tested independently with a common schema for input objects, output objects, provenance fields, and confidence metadata. In the second stage, agents will be connected to the orchestrator through a shared invocation protocol, allowing the base LLM to issue structured requests and receive structured evidence responses. In the third stage, we will compose agents into end-to-end workflows corresponding to the two Phase I demonstration tasks: **antigenic escape assessment** and **cross-species adaptation analysis**.

A core integration requirement is that all agent outputs remain **auditable and reusable**. To satisfy this requirement, every agent invocation will generate a machine-readable record containing the task identifier, agent identifier, model or tool version, parameter configuration, input summary, output summary, timestamp, and confidence metadata. These records will be attached to the workflow trace and made available both for internal debugging and formal evaluation. This design supports the project’s broader goal of building a **sovereign scientific model stack**, in which training artifacts, workflow traces, and derived reasoning products can be inspected and reproduced in trusted scientific computing environments. It also aligns with the Genesis Mission platform philosophy that successful models and workflows should be shareable, discoverable, and reusable within larger national scientific AI ecosystems.

The integration strategy also includes explicit handling of **uncertainty and abstention**. Because scientific reasoning workflows often face incomplete, noisy, or conflicting evidence, agents will be permitted to return low-confidence outputs, ambiguity flags, or abstention signals rather than overcommitting to weak conclusions. The orchestrator will incorporate these signals when deciding whether to invoke additional agents, request clarifying evidence, or terminate with a conservative conclusion. This is important both scientifically and evaluatively: a credible scientific AI system should be judged not only by its ability to produce answers, but by its ability to recognize when evidence is insufficient.

### 3.3 Demonstration Workflows

Phase I evaluation will center on two representative workflows chosen because they are scientifically meaningful, computationally heterogeneous, and highly relevant to cross-domain viral reasoning.

The first workflow, **antigenic escape assessment**, begins from a sequence variant or mutation set and asks whether the evidence supports concern for altered antigenic properties. The orchestrator will use the Viral Protein Foundation Agent to obtain mutation-context priors and representation-based novelty signals, the Structure Reasoning Agent to evaluate epitope-region and receptor-proximal implications, the Evolutionary Dynamics Agent to assess plausibility and historical context, the Evidence Agent to retrieve supporting or contradictory literature, and the Quantitative Inference Agent to calibrate and rank resulting hypotheses. The final output will be an auditable, uncertainty-aware assessment that explains not only the conclusion, but the evidence chain that led to it.

The second workflow, **cross-species adaptation analysis**, begins from a sequence, mutation profile, or candidate variant and asks whether the available evidence is consistent with host-adaptive change. This workflow will place greater emphasis on mutation-context interpretation, evolutionary plausibility, and evidence reconciliation across known host-associated patterns. Here again, the multi-agent design is important because no single model or tool is likely to provide a sufficient basis for mechanistic reasoning. These workflows directly instantiate the FOA’s vision of AI systems that generate scientific insight by integrating multiple models and tools in an iterative analysis process. 

### 3.4 Evaluation Framework and AI Advantage Metrics

Evaluation is central to the entire Phase I design. The FOA explicitly states that success in Phase I may include increased predictive power, stronger scientific insight, tighter coupling of data and hypotheses, identification of scaling metrics, improved workflows, or other quantitative indicators proposed by the team. Our evaluation framework will therefore assess the system at three levels: **component performance**, **workflow performance**, and **AI advantage trajectory**. 

At the **component level**, we will examine whether each agent is functioning as intended. For the viral protein foundation model, we will assess representation quality through downstream mutation-ranking and context-sensitivity analyses. For the orchestrator, we will evaluate task decomposition accuracy, tool-routing consistency, and evidence-synthesis reliability. For the other agents, we will examine the quality and stability of their structured outputs, including whether confidence and provenance fields are correctly populated and reusable in later workflow stages.

At the **workflow level**, we will compare the full multi-agent system against three baseline categories:
(1) **single-model baselines**, in which a single general model attempts the reasoning task without modular agent support;
(2) **non-agentic compositional baselines**, in which tools are manually chained but not coordinated by a reasoning model; and
(3) **manual or expert-assembled workflows**, in which the same tools are used outside the agent framework.
Performance metrics will include predictive utility, reasoning coherence, evidence traceability, uncertainty calibration, and time-to-hypothesis. These measures are designed to reflect the FOA’s emphasis on scientific workflow quality, not only raw task accuracy.

At the level of **AI advantage trajectory**, we will evaluate whether the system shows measurable improvement as additional information sources or model capacity are added. For example, we will test whether performance improves when moving from sequence-only reasoning to sequence-plus-structure reasoning, or from limited agent composition to fuller evidence integration. We will also examine whether the system’s outputs become more stable, better calibrated, or more traceable as additional agents are included. This is important because the FOA is not asking only whether a fixed prototype works; it is asking whether the prototype demonstrates a credible path toward a **transformative scientific capability** under expanded data, compute, and model integration. 

### 3.5 Expected Phase I Deliverables

By the end of Phase I, we expect to deliver:
(1) a prototype governed base scientific LLM adapted for agentic orchestration;
(2) a prototype from-scratch viral protein foundation model;
(3) a modular multi-agent integration framework with standardized interfaces, provenance logging, and uncertainty propagation;
(4) two working demonstration workflows for antigenic escape assessment and cross-species adaptation analysis;
(5) a quantitative evaluation report comparing the system to single-model, non-agentic, and manually assembled baselines; and
(6) a Phase II scaling roadmap describing how the prototype architecture can be expanded in model scale, tool coverage, scientific breadth, and computing integration. These deliverables satisfy the core expectations of Phase I by providing a clear research workflow, quantitative validation, and a credible path toward broader scientific impact.

### 3.6 Technical Risk and Mitigation

The primary technical risks in Phase I are integration failure, weak orchestration behavior, and insufficient measurable improvement over baselines. We address these risks through three strategies. First, we reduce integration complexity by enforcing shared schemas and staged assembly rather than attempting end-to-end coupling from the outset. Second, we bound model ambition in Phase I by adapting the base LLM and training only a prototype-scale viral protein foundation model, preserving effort for evaluation and workflow validation. Third, we define success using multiple complementary metrics—including traceability, calibration, and workflow efficiency—so that the system can demonstrate value even when raw predictive gains are modest. This is consistent with the FOA’s broad framing of AI advantage as encompassing predictive performance, insight generation, workflow improvement, and scaling evidence. 

Taken together, this training, integration, and evaluation plan is intended to show that **SOVEREIGN-VIROFM** is not simply a collection of models, but a scientifically grounded prototype of a new class of modular, sovereign, multi-agent foundation model systems.
